# تست واقعی داخل Telegram با Render رایگان + Supabase

این تنظیمات فرانت‌اند و بک‌اند را روی یک Web Service و یک دامنه HTTPS قرار می‌دهد. Netlify لازم نیست؛ کوکی‌های ورود و Socket.IO هم‌مبدأ می‌مانند. کاربر داخل Telegram تست می‌کند، نه روی localhost. این فایل برای Staging است و هنوز روی حساب شما اجرا نشده است.

## قبل از انتشار

1. افزونه Render را نصب و حساب خود را متصل کنید، یا وارد داشبورد Render شوید.
2. سورس را در مخزن خصوصی GitHub قرار دهید. ریشه مخزن باید شامل package.json و render.yaml باشد. `.env` و node_modules را وارد مخزن نکنید.
3. Supabase پروژه آزمایشی را نگه دارید؛ DATABASE_URL و DIRECT_URL را با رمز جدید از بخش Connect بردارید. برای Migration از اتصال مستقیم قابل دسترسی یا Session Pooler استفاده کنید. Service Role Key فقط در تنظیمات سرور قرار می‌گیرد.
4. Bot را با BotFather بسازید. برای دریافت Stars از فروش اشتراک به Telegram Premium شخصی نیاز ندارید؛ پرداخت به موجودی Bot می‌رود.

## انتشار

- در Render، New → Blueprint و مخزن GitHub را انتخاب کنید. render.yaml یک Web Service رایگان و یک Key Value رایگان در Frankfurt تعریف می‌کند. اگر سهمیه سرویس رایگان قبلاً مصرف شده باشد، همان‌جا توقف کنید؛ پلن پولی خودکار انتخاب نکنید.
- Secretهای خواسته‌شده را فقط در Render وارد کنید. TELEGRAM_WEBHOOK_SECRET خودکار تولید می‌شود.
- Build: `npm ci --include=dev && npm run db:generate && npm run build`
- Start: `npm run start:render`
- ریشه پروژه URL اختصاصی `https://...onrender.com` می‌گیرد. برنامه از RENDER_EXTERNAL_URL برای FRONTEND_URL و آدرسهای عمومی استفاده می‌کند. برای دامنه سفارشی، FRONTEND_URL را صریح تنظیم کنید.
- هیچ Migration پیش‌فرض اجرا نمی‌شود. بعد از تأیید اینکه مقصد واقعاً دیتابیس آزمایشی تازه شماست، APPLY_MIGRATIONS را موقتاً true کنید و Deploy را اجرا کنید. پس از موفقیت، آن را false کنید. گزینه جایگزین اجرای `npm run db:migrate` از ترمینال کامپیوترتان به دیتابیس ابری است؛ این به معنای تست برنامه روی localhost نیست.
- برای ساخت پلن‌ها/Policyها، `.env` محلی را فقط برای اسکریپت مدیریت به دیتابیس ابری تنظیم کنید و `node --import tsx scripts/init-production.ts` را اجرا کنید. بعد از اولین ورود مدیر، همین اسکریپت را دوباره اجرا کنید تا حساب Allowlist ارتقا یابد. اسکریپت فعلاً به صورت خودکار در Render اجرا نمی‌شود.
- Seed عمومی یا ورود جعلی را در انتشار اینترنتی فعال نکنید. این تنظیمات از احراز هویت واقعی Telegram استفاده می‌کنند و حساب‌های ساختگی در حالت production از Discovery حذف می‌شوند. برای تست کامل به دو یا چند حساب واقعیِ تحت اختیار تست‌کنندگان نیاز دارید؛ سناریوی نمایش حساب‌های ساختگی در staging نیاز به تنظیم جداگانه محدود به تست‌کنندگان دارد.
- URL نهایی، Token و Webhook secret را در `.env` مدیریتی تنظیم و `npm run bot:setup` را اجرا کنید، یا در مرحله اتصال حساب‌ها این کار را با ابزار مجاز انجام می‌دهیم. این دستور تنظیمات Bot واقعی را تغییر می‌دهد. آن را فقط بعد از آماده‌شدن آدرس اجرا کنید.
- در BotFather، Mini App را فعال و آدرس HTTPS را ثبت کنید. سپس از `/start` → Open Vela وارد شوید.

## محدودیت‌های رایگان

Render پس از ۱۵ دقیقه بدون ترافیک ورودی می‌خوابد؛ راه‌اندازی مجدد حدود یک دقیقه است. کارهای Outbox در این پیکربندی در همان پردازه API اجرا می‌شوند و هنگام خواب متوقف‌اند؛ پس از بیداری ادامه می‌یابند. داده صف در PostgreSQL است، نه حافظه Redis. این حالت برای حذف/اعلان فوری یا پرداخت عمومی قابل اتکا نیست. برای تست پرداخت ابتدا برنامه را باز کنید و منتظر بارگذاری کامل بمانید؛ pre_checkout_query تلگرام مهلت کوتاه دارد.

Key Value رایگان پس از Restart داده‌اش را از دست می‌دهد؛ این نسخه فقط rate limit را در آن نگه می‌دارد. حساب‌ها، اشتراک‌ها، پیام‌ها و صف در Supabase باقی می‌مانند. تصویرها نیز در Bucket خصوصی هستند. بدون اجازه به پلن پولی ارتقا ندهید. اگر محدودیت ترافیک/سهمیه برسد سرویس ممکن است متوقف شود.

این نسخه تغییرات ویژه Render را با تست محلیِ بدون اتصال خارجی بررسی می‌کند؛ راه‌اندازی واقعی منوط به حساب Render، مخزن کد و تنظیم Secretها است. نسخه پایه هنوز گزارش تست اصلی را در release-checklist.md دارد؛ تست‌های اضافه Render در hosting.test.ts هستند.
